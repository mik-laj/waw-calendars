# Changelog

Dated notes describing what changed in the project and why, to preserve context
across sessions. One file per entry, named `YYYY-MM-DD-short-slug.md`.

Each entry should cover:

- **What** changed (features, fixes, structural changes).
- **Why** — the motivation or problem being solved.
- **Notes** — trade-offs, follow-ups, or anything non-obvious.

Keep entries short. This is narrative context, not a git log replacement.
